# 架构说明

## 技术栈

- **核心**：Rust（axum web / clap CLI / rusqlite / reqwest）
- **前端**：原生 HTML/JS/CSS（无框架，编译期 `include_str!` 内嵌进二进制）
- **菜单栏**：Objective-C（NSPanel + WKWebView，clang 现场编译）
- **数据库**：SQLite（对话 turns / 图片资产），WAL 模式
- **推理后端**：OpenAI 兼容协议（llama.cpp / Ollama / 任意云端 API）

## 目录结构

```
src/
├── main.rs            # 入口，模块注册
├── cli.rs             # CLI 命令 + REPL + 工具注册（build_tool_registry）
├── config.rs          # 配置（jsonc）、provider、persona、watcher 相关
├── provider.rs        # 供应商管理（发现模型/增删改切）
├── agent/mod.rs       # agent 主循环（run_turn、工具调用、模式）
├── llm/               # LLM 客户端（openai_compatible 流式、pi_rpc）
├── state/             # SQLite 存储（conversation_db、usage、记忆）
├── web.rs             # axum 路由（/api/*、SSE 事件流、静态资源）
├── speech.rs          # TTS（say）/ STT（SFSpeechRecognizer）
├── tools/             # 工具注册表 + 各工具（web/memes/memory/providers...）
├── finetune.rs        # 训练数据采集（JSONL，只收集不训练）
├── prompts/           # 内置人格/提醒（gqy.md/chat.md/plan.md/compact.md）
└── scripts/           # swift 辅助（speech-tool/vision-tool）
web/                   # WebUI 静态资源（内嵌）
macos/GQYMenuBar/      # 菜单栏 App 源码（build.sh/make-dmg.sh）
communication/         # TG/NapCat 通信桥（v2 接 daemon）
wiki/                  # 项目文档（同步到 GitHub Wiki）
```

## 数据流

```
用户输入（终端/WebUI/桥）
  → agent::run_turn
      → start_turn（SQLite，记录 mode）
      → chat_messages（按 mode 加载历史：闲聊只取最近12轮）
      → LlmClient（provider 路由 → OpenAI 兼容端点）
      → 流式 chunk（SSE 事件流 → WebUI/终端实时渲染）
      → 工具调用循环（registry 分派）
      → complete_turn（写库 + usage 统计 + finetune 采样 + 记忆处理）
      → Git 快照备份（backup）
```

## 关键机制

### config watcher（热重载）

后台线程监听 `config.jsonc` 的 mtime → 变化时 reload agent + LLM client → 发布 `config.reloaded`（SSE）→ WebUI 自动刷新。这就是"改配置不用重启"的基础。

### 模式隔离（0.8.2+）

`turns` 表加 `mode` 列：`start_turn` 记录模式；加载历史按模式过滤（`load_visible_turns_for_mode`）——闲聊 `mode='chat'` 独立、限量 12 轮，普通/计划排除 chat。

### 流式 think 剥除（0.8.3+）

`handle_sse_line` 里的 `scrub_think_stream` 跨 chunk 状态机剥掉 `<think>...</think>`（Qwen3 系 no-think 也会输出空块），全局生效。

### 聊天通道（channel）

进程级通道（terminal/webui/qq/tg），`GQY_CHANNEL` 环境变量隔离；同进程内模式隔离由 `mode` 列实现。
