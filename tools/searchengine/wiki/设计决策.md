# 设计决策

本文记录两个关键设计取舍的**原因与代价**，方便后人理解与调整。

## 1. 英文优先：刻意不处理中文（CJK）

### 现象
中文搜索生态的**信噪比显著低于英文**：
- SEO 商业化严重，内容农场、采集站、伪原创泛滥。
- 营销/权重页大量挤占召回位，干净结果被稀释。
- 纯英文检索（DuckDuckGo / Google）召回质量高一个量级。

### 决策
- `tokenizer.py` **只处理拉丁字母+数字**，完全不切分 CJK。
- `crawler.py` 的 `looks_english()` 从源头跳过非英文页（`<html lang>` 或拉丁占比 ≥55%）。
- 中文查询**优雅降级**：返回零结果，不报错。

### 代价
- 无法直接搜中文语料。若日后需要，可接入 `jieba` 做中文分词（见[扩展指南](扩展指南.md)），
  但**不推荐**直接回归「中文优先」——那会把农场噪声重新引入。
- 中英文混排页面里，仅 `iPhone` / `Kubernetes` / `v1.30` 这类拉丁 token 被索引，符合预期。

### 适用场景
个人搜索后端、技术文档检索、英文知识库——这些场景英文优先收益最大。

## 2. 农场黑名单：双层拦截

### 问题
英文世界本身也混着大量低质源：内容农场（PBN）、问答农场、链接目录、采集站。
它们靠关键词堆砌排名，污染召回。

### 决策：双层防御
1. **采集端**（`crawler.py`）：抓取前用 `DomainBlocklist` 拦黑名单域，且**不把其外链入队**，
   避免顺着农场链接扩散。
2. **索引端**（`indexer.py`）：`build_index(blocklist=...)` 二次过滤，
   即使采集端漏过（如黑名单更新滞后），索引时仍剔除。

### 匹配规则
- **后缀匹配**：`csdn.net` 规则同时拦掉 `blog.csdn.net` 等子域（`host == rule` 或 `host.endswith("."+rule)`）。
- 默认清单 `DEFAULT_FARM_DOMAINS` 含 34 个典型噪声源（内容农场 / 问答农场 / 目录 / 中文采集站 / 低质聚合）。
- 可扩展：自定义黑名单文件（`data/blacklist.txt` 或 `--blacklist-file`），每行一个域名，`#` 开头为注释。

### 代价与边界
- 黑名单是**保守的**——宁可漏放，不可误杀正常站。默认清单偏典型、长期被诟病的源。
- 它不是万灵药：新的农场站会不断冒出，需持续维护清单。
- 若要更强净化，应接 **Brave Search / Google CSE** 等带反垃圾排序的上游（见扩展指南），
  而非仅靠域名黑名单。

## 为什么不一步到位做分布式 / ML 排序？

本项目定位是**可跑通的原型 + 自用后端**，不是生产级搜索引擎。分布式爬虫、海量倒排存储、
PageRank、ML 排序都是明确已知的扩展方向（见[扩展指南](扩展指南.md)），但不在当前范围——
保持零依赖、可阅读、可改，比追求规模更重要。
