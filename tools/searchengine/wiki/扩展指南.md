# 扩展指南

本项目是原型，以下方向都已预留扩展点，按需取用。每一项都标注了**改动文件**与**大致工作量**。

## 1. 中文支持（jieba 分词）
- **改动**：在 `tokenizer.py` 接入 `jieba`（需 `pip install jieba` / venv），
  对 CJK 段做词典分词，替代当前的「不处理」。
- **注意**：启用中文会重新引入农场噪声，建议同时保留[设计决策](设计决策.md)里的英文优先与黑名单。
- **工作量**：小（分词器 + 停用词表）。

## 2. PageRank 链接排序
- **改动**：`crawler.py` 抓取时额外产出 `graph.jsonl`（`<from, to>` 边）；
  `query.py` 的 `search()` 把 BM25 分数与 PageRank 线性融合：
  `final = (1-λ)·bm25 + λ·pagerank`。
- **收益**：结果更像 Google，权威页上浮。
- **工作量**：中（幂迭代 + 融合）。

## 3. 换上游：Brave / Google CSE
- **动机**：仅靠域名黑名单不足以净化英文召回；商业搜索 API 自带反垃圾排序。
- **改动**：新增 `search_api.py`，实现 `SearchBackend` 接口（`search(q, top_k)`），
  在 `query.py` 里作为可选后端（当配置了 API key 时优先）。
- **工作量**：小（HTTP 调用 + 结果归一化）。

## 4. 增量索引
- **改动**：`indexer.py` 支持合并已有 `postings.json`（按 doc_id 增量更新），
  `crawler.py` 支持断点续爬（manifest 去重续传）。
- **收益**：大站点可分批建索引，不必每次全量。
- **工作量**：中。

## 5. 质量过滤增强
- 域名**白名单模式**：只索引信任的少数站点（个人知识库场景）。
  在 `DomainBlocklist` 增加 `whitelist` 模式或新增 `Whitelist` 类。
- 正文质量启发式：按文本密度（如 boilerpipe 思路）剔除导航/广告，提升索引信噪比。
- **工作量**：小。

## 6. 接进 GQY（顾清影）
- **思路**：把本引擎包装成 GQY 的一个 `gqy_*` 工具（见 GQY 的 `src/tools/` 扩展机制），
  或作为一个独立本地搜索 provider，让 GQY 的 `web_search` 可调用。
- **改动**：用 GQY 的 tool 描述 JSON 暴露 `search(q, top_k)`，后端调用本项目的 `query.search()`。
- **工作量**：中（需对齐 GQY 工具协议）。

## 7. 分布式 / 规模化的边界
当前是**单机内存索引**（postings 用 dict 存 JSON）。要搜「整个互联网」量级，需要：
- 爬虫改为 Scrapy / 集群调度；
- 倒排索引改用 Lucene / Elasticsearch / RocksDB 级存储；
- 排序引入 ML 召回。
这些是明确已知的下一步，但超出本原型范围——保持零依赖、可读、可改是优先级。

## 贡献约定
- 默认农场清单 `DEFAULT_FARM_DOMAINS` 偏保守：只收典型、长期被诟病的源，避免误杀。
- 新增黑名单域名请附一句来源说明（为何是农场/垃圾站）。
- 改 BM25 参数（`k1` / `b`）或 `TITLE_BOOST` 请在 commit 里说明动机。
